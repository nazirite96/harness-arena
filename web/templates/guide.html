{{ event_name }} 참가 방법

팀이 opencode 설정 번들(에이전트 프롬프트 · 훅 · 커스텀 툴 · 지침)을 만들어 제출하면, 서버가 고정 모델·고정 버전으로 SWE-bench Verified 문제를 자동 실행·채점하고 리더보드에 올립니다. 여러분이 바꾸는 것은 하네스이고, 모델과 도구 루프는 모두 같습니다.

opencode {{ opencode_version }}모델 {{ model_alias }}문제당 {{ timeout_min }}분 · ${{ cost_cap }}dev 예산 ${{ dev_budget }}/팀

한눈에 보기

제출물git 저장소의 특정 커밋 (번들 루트에 arena.yaml) 문제 셋Public 50 (공개, 일일 리더보드) · Private 100 (비공개, 최종 채점) · Dev 5 (즉시 실행용, Public의 부분집합) 지표해결률 = 테스트를 통과한 문제 비율. 동점이면 문제당 평균 비용이 낮은 팀 우위 최종 점수0.7 × Private 해결률 + 0.3 × 발표 점수 (Private는 2회 실행 평균) 제출 제한공식 제출 하루 1회, 22:00 KST 마감 → 23:00 배치 실행 → 다음날 08:00 전 리더보드 갱신. dev 실행은 팀 예산 내 무제한 참조 행baseline/opencode-vanilla, reference/oh-my-opencode — 순위에 들지 않는 비교 기준

팀 토큰과 프록시 키 받기

운영진에게서 팀 토큰 tm_…(제출·팀 페이지용)과 프록시 키 sk-…(로컬 opencode가 대회 모델을 쓰기 위한 키, 팀 dev 예산에서 차감)를 받습니다. 못 받았으면 {{ contact }}.

opencode 고정 버전 설치

npm install -g opencode-ai@{{ opencode_version }}
opencode --version

대회 서버도 같은 버전을 씁니다. 다른 버전으로 개발하면 훅 API가 달라 동작이 다를 수 있습니다.

스타터 킷 복사 + 프록시 연결

git clone {{ starter_kit_url or '<스타터 킷 주소>' }} my-bundle

bundle/가 여러분의 번들입니다. 로컬에서 대회 모델을 쓰려면 번들 밖의 개인 설정 ~/.config/opencode/opencode.json에 아래를 추가합니다. (번들 안에 넣으면 검증에서 거부됩니다.)

{
  "model": "arena/{{ model_alias }}",
  "provider": {
    "arena": {
      "npm": "@ai-sdk/openai-compatible",
      "options": { "baseURL": "{{ proxy_url }}", "apiKey": "{env:ARENA_API_KEY}" },
      "models": { "{{ model_alias }}": { "name": "{{ model_alias }}", "tool_call": true,
                  "limit": { "context": 200000, "output": 32000 } } }
    }
  }
}
export ARENA_API_KEY=sk-…   # 받은 프록시 키

로컬에서 번들 시험

아무 파이썬 저장소에서 번들을 적용해 TUI로 대화해 보고, 대회와 같은 헤드리스 방식으로도 돌려 봅니다.

cd /path/to/some-python-repo
cp -r /path/to/my-bundle/bundle/.opencode . && cp /path/to/my-bundle/bundle/AGENTS.md .
opencode --agent main                    # TUI
opencode run --agent main "README 오타를 찾아 고쳐줘"   # 헤드리스

훅이 살아 있으면 [arena-hooks] … 메시지가 보입니다.

번들 구조 지키기 (제출 계약)

bundle/
  arena.yaml                team, main_agent, description   (필수)
  opencode.json             instructions 등 (model / provider / permission 금지)
  AGENTS.md                 저장소 루트(/testbed)에 복사되는 지침
  .opencode/agents/*.md     에이전트 정의. main_agent 파일 필수
  .opencode/plugins/*.ts    훅·커스텀 툴 플러그인
  .opencode/tools/*.ts      커스텀 툴 (파일명 = 툴 이름)
  .opencode/skills/**       스킬 (선택)
  package.json              플러그인 의존성 (선택)
  • 폴더 이름은 복수형(agents/ plugins/ tools/)만 인정
  • 5MB 이하 · 바이너리 금지 · npm 플러그인 참조 금지 · 완성형 에이전트 플러그인(oh-my-opencode 등) 의존성 금지
  • model, provider, permission은 운영진이 덮어씁니다. 모든 에이전트(서브에이전트 포함)는 같은 모델을 씁니다
  • 문제 ID(django__django-12345 같은)를 하드코딩하면 거부됩니다

검증하기

arena validate ./bundle

항목별로 한국어 오류가 나옵니다. [통과]가 나와야 제출됩니다. 팀 페이지의 제출 폼도 같은 검증을 거칩니다.

dev 실행 요청 (즉시 · Dev 5문제 · 팀 예산 차감)

git add -A && git commit -m "hooks: block edit before repro" && git push
arena submit https://github.com/<team>/<repo>.git $(git rev-parse HEAD) --channel dev

또는 팀 페이지의 폼에 저장소 URL과 커밋 SHA를 넣습니다. 끝나면 팀 페이지에 문제별 결과와 궤적 링크가 뜹니다.

공식 제출 (하루 1회 · 22:00 KST 마감)

arena submit https://github.com/<team>/<repo>.git <sha> --channel official

23:00 배치에서 Public 50문제를 실행하고 아침 리더보드에 반영됩니다. 하루에 두 번 내면 두 번째는 거부됩니다.

궤적 읽고 개선하기

팀 페이지 → 실행 → 셀 클릭. 단계별 모델 메시지, 툴 호출과 인자, 툴 출력, 토큰·비용이 보입니다. 확인할 것:

  • 재현 없이 편집했는가 · 종료 전 테스트를 실행했는가
  • 같은 명령을 반복하는가(doom loop) · 어디서 시간과 예산을 다 썼는가
  • 서브에이전트가 편집까지 해서 컨텍스트를 잃었는가

발표(30%)의 핵심은 어떤 훅/프롬프트 변경이 어떤 궤적 변화를 만들었는지를 궤적으로 증명하는 것입니다.

자주 나오는 실패 패턴

  1. 재현 없이 추측으로 수정 → 관련 없는 파일 변경, 테스트 실패
  2. 전체 테스트 스위트 실행 → {{ timeout_min }}분 시간 초과
  3. 서브에이전트에게 편집을 맡김 → 컨텍스트 유실
  4. 종료 전 테스트 미실행 → session.idle 훅으로 재프롬프트하면 개선
  5. pip install·외부 접근 시도 → 네트워크가 차단되어 시간만 낭비

규칙 요약

  1. 제출물은 제출 계약을 따르는 opencode 설정 번들만 인정
  2. 기존 에이전트 제품·플러그인을 통째로 제출 금지. 일부 차용은 출처 표기 시 허용
  3. 번들을 만드는 데 Claude Code 등 코딩 에이전트 사용은 자유
  4. 문제 ID·레포·이슈 힌트 하드코딩 금지 · 외부 네트워크 접근 시도 금지
  5. 공식 제출 하루 1회(22:00 KST) · 코드 프리즈 D9 18:00
  6. 최종 순위 = Private 70% + 발표 30% · 상위 3팀은 코드 리뷰·재현 확인 후 확정
  7. 프록시 로그(프롬프트·응답 포함)는 운영진이 운영·교육 목적으로 열람
  8. 위반 시 해당 제출 무효, 반복 시 실격

FAQ

다른 모델을 쓸 수 있나요?

아니요. 모든 팀이 같은 모델 하나를 씁니다. 번들에 model을 적어도 덮어써집니다.

dev 예산이 다 떨어지면?

dev 실행 요청이 거부됩니다. 잔액은 팀 페이지에 표시됩니다. 공식 제출은 운영진 예산으로 돌아가므로 영향이 없습니다.

Private 문제는 언제 볼 수 있나요?

최종 발표 전까지 어떤 페이지에도 나오지 않습니다. Public과 겹치지 않고 레포 분포는 비슷합니다.

번들 안에서 인터넷을 쓸 수 있나요?

실행 중 컨테이너는 프록시만 접근할 수 있습니다. 검색·웹페치 도구는 실패합니다. 훅으로 미리 꺼 두는 것을 권합니다.

궤적은 다른 팀도 보나요?

팀은 자기 궤적만 봅니다. 운영진은 전체를 봅니다.
